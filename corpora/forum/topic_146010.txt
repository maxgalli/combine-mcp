REPLY 3 (by amarini @ 2026-06-15T21:14:07.289Z):
Ciao Andrea,
Adding to Giacomo’s point, you can provide +/- n sigma points (instead of +/- 1) and use a 1/n factor in the datacard definition. This approach models certain regions of the phase space more as an interpolation rather than an extrapolation (see the link below). This construct was used, for example, in a simplified variation of the Hgg Run 1 analysis (though not the fully parametric one described in the paper).
Returning to your question: the core issue is understanding how a bin generally morphs between n given points. Currently, with two points (plus the nominal), we already have two reasonable interpolation schemes for the yields (shape and shapeN, as described here). We have also considered different interpolation schemes, but ultimately, we must balance computational simplicity with boundary conditions (e.g., keeping the likelihood L continuous and differentiable). Polynomials perform well in these respects.
With more points, the yield interpolation can become overconstrained. One has to choose between a fit or a spline in the interpolation region , and then adapt while still guessing an extrapolation regime. [**]
Ultimately, neither approach seems to solve every problem. With fits, for instance, one must always ensure that the curve passes through the nominal point and remains reasonably continuous; however, the resulting interpolated yields can sometimes look strange. For example, if you have N points, would you rather accept that the interpolation might deviate significantly at, say, the 3rd point? Or would you prefer the yields to have multiple local maxima and minima (and then have to figure out if you’re stuck in the wrong one)? Furthermore, how do you extrapolate? Do you use N and N-1, or N and the 0th point? What if these points are affected by statistical fluctuations?
Combine is very versatile. If you want to study this further, the easiest way to implement the morphing might be using alternative constructs. If you identify one channel (in Combine jargon) per bin of your histogram, you can use the rateParam, param, and extArgs constructs to create a multiplicative nuisance (ideally similar to a logNormal in each bin) with an arbitrary modeling scheme for either the constraint or the rate itself. A similarly detailed approach can likely be constructed for a histogram using RooParametricHist [*]. If I recall correctly, a version of this approach was studied and used by the HH analyses in Run 2 to model logNormal uncertainties with a variable sigma constraint as a function of the POI.
In summary, I believe we need an operational definition of what constitutes a “proper” interpolation or extrapolation. If it isn’t obvious with 3 points, it certainly won’t be easier with 5, 7, or 9.
Cheers,
-Andrea
[*] N.B. There is a slight difference here, residing in the fact that Combine currently treats normalization as a separate quantity.
[**] In this context, a “fit” means you have N points plus some eventual constraints, and you accept that the interpolation scheme does not necessarily pass through all of them. A “spline” implies a functional construct that passes exactly through all the points, again with potential constraints.

REPLY 5 (by amarini @ 2026-06-19T12:48:58.700Z):
Hi Andrea,
Provided that the scaling to production datacards needs to be assessed. Combine at the moment is optimized for certain set of common operations.
For efficiencies, we could try to go back to the ratio of events from the binomial distribution or the ratio of Poisson.
At the moment your likelihood is (with lognormal and one bin)

\mathcal{L}_0 = \mathcal{P}(\dots+ s' k^\theta + b \dots) \mathcal{N}(0,\theta,1)

where k=\sigma_\hat{p}/\hat{p} is the relative error, and s' = s_0 \hat{p} is the corrected yield. \mathcal{P} ~ Poisson, \mathcal{N} ~ Gaussian.
Intuitively for a binomial we would like the overall likelihood to look like:

\mathcal{L} = \mathcal{p}(\dots+s_0 p \dots ) \mathcal{B}(m;n,p)

If you think it comes from ~ the ratio of two poisson parameters is just a matter of including the relevant scaling parameters in CR (w/ r a freely floating nuisance parameter, profiled in the likelihood). It should be exact but computationally more expensive than the line above (TBC, intuitively should be P*B and we profile over the rate, but I didn’t do all the calculations; in anycase the image is spot on :D)

\mathcal{L}_1 = \mathcal{P}(\dots s_0 p +b \dots) \mathcal{P}(m;p r) \mathcal{P}(n-m;r (1-p))

For the Binomial constrain (\hat{p}=m/n), if we accept a bit of an approximation, we can write it with a Poisson as well as

\mathcal{L}_2 = \mathcal{P}(\dots) \mathcal{P}(m,n \cdot p)

or (if you are closer to 100% effiiency)

\mathcal{L}_2 = \mathcal{P}(\dots) \mathcal{P}(n-m,n \cdot (1-p))

Note that all the above, after switching to the Poisson distribution could be implemented as CR and rateParameters.
